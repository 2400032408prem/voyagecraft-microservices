1. Executive Summary & Problem Analysis

Modern online travel booking platforms manage high volumes of concurrent operations: real-time package inventory, secure customer authentication, credit card transaction handling, and multi-step reservation workflows. Building such platforms as a monolithic application leads to architectural pitfalls: tight database coupling, cascading service failures, inability to scale critical components independently, and high deployment risks.

VoyageCraft addresses these challenges by implementing a decoupled, resilient, and cloud-native Microservices Architecture aligned with Domain-Driven Design (DDD) principles. The application isolates distinct business capabilities into independent, self-contained microservices communicating via dynamic service discovery, reactive API gateway routing, and declarative REST clients.

Core Architectural Principles Demonstrated:

  • Service Autonomy: Each service possesses its own codebase, build lifecycle, and database (Database-per-Service pattern).
  • Single Point of Ingress: Clients communicate strictly through the API Gateway, shielding internal topology.
  • Dynamic Discovery: Services register dynamically with Netflix Eureka, eliminating hardcoded hostnames and ports.
  • Cryptographic Security: Stateless JSON Web Tokens (JWT) signed with HMAC-SHA256 and BCrypt password encryption.
  • Declarative RPC: Spring Cloud OpenFeign orchestrates inter-service transactions cleanly with zero boilerplate HTTP code.

3. Deep Dive into Core Microservices

3.1 Service Discovery (Eureka Server)

The eureka-server provides a dynamic lookup directory. Instead of hardcoding physical network addresses (e.g. http://192.168.1.50:8082), each service registers its logical application ID (e.g., PACKAGE-SERVICE) on startup. Eureka maintains continuous health tracking via heartbeat pings every 30 seconds.

Configuration Highlights: 
server:
  port: 8761
eureka:
  instance:
    hostname: localhost
  client:
    register-with-eureka: false  # Server does not register with itself
    fetch-registry: false        # Does not pull registry from peer

3.2 API Gateway & Routing Engine

The api-gateway leverages Spring Cloud Gateway on top of Project Reactor (WebFlux non-blocking I/O). It handles unified ingress, prevents direct exposure of backend microservices, applies global CORS headers, and dynamically load-balances across registered instances using the lb:// prefix.

Reactive Routing & CORS Configuration: 
server:
  port: 9090
spring:
  cloud:
    gateway:
      server:
        webflux:
          globalcors:
            cors-configurations:
              '[/**]':
                allowed-origins: "*"
                allowed-methods: [GET, POST, PUT, DELETE, OPTIONS]
                allowed-headers: "*"
          routes:
            - id: auth-service
              uri: lb://AUTH-SERVICE
              predicates:
                - Path=/auth/**
            - id: package-service
              uri: lb://PACKAGE-SERVICE
              predicates:
                - Path=/packages/**
            - id: booking-service
              uri: lb://BOOKING-SERVICE
              predicates:
                - Path=/bookings/**
            - id: payment-service
              uri: lb://PAYMENT-SERVICE
              predicates:
                - Path=/payments/**

3.3 Authentication Service & JWT Token Lifecycle

The auth-service implements modern stateless token authentication. Upon user registration, passwords are salted and hashed using BCryptPasswordEncoder. Upon login, credentials are verified by the Spring Security AuthenticationManager, and a signed JWT containing username claims and a 24-hour expiration timestamp is generated using the HMAC-SHA256 algorithm.

Security Architecture Summary:
  • Password Storage: BCrypt.hashpw(password, gensalt(10)) - strictly irreversible.
  • JWT Signing: 256-bit cryptographically secure hexadecimal secret key.
  • Session Policy: SessionCreationPolicy.STATELESS - zero server-side session memory consumption.

3.4 Package Service & Capacity Inventory Management

The package-service provides full CRUD capabilities for travel packages and handles inventory allocation. The critical endpoint PUT /packages/{id}/reduce-capacity performs atomic boundary checks: if capacity > 0, it decrements the available slots and persists the change; if slots are exhausted, it throws an exception to reject the booking.

3.5 Payment Service

The payment-service simulates financial authorization and persists audit records with transaction IDs, amounts, and statuses (SUCCESS / FAILED).

3.6 Booking Service & OpenFeign Orchestration

The booking-service is the transaction coordinator. When a user requests a new booking:

  1. It persists an initial Reservation entity in PENDING status.
  2. It calls paymentClient.processPayment(...) via OpenFeign to process the transaction.
  3. If payment responds with SUCCESS, it calls packageClient.reduceCapacity(...) to decrement available inventory.
  4. It updates the reservation status to CONFIRMED and returns the final record.
  5. If any remote call fails or is rejected, it transitions the reservation status to FAILED.
Declarative Feign Client Interface: 
@FeignClient(name = "PAYMENT-SERVICE")
public interface PaymentClient {
    @PostMapping("/payments/process")
    Map<String, Object> processPayment(@RequestBody Map<String, Object> payment);
}

@FeignClient(name = "PACKAGE-SERVICE")
public interface PackageClient {
    @PutMapping("/packages/{id}/reduce-capacity")
    Map<String, Object> reduceCapacity(@PathVariable("id") Long id);
}

5. System Startup & Execution Guide

5.1 Prerequisites

  • Java Development Kit: JDK 17 or higher (Verified with OpenJDK 17/21).
  • Build Tool: Apache Maven 3.8+ (or Maven Wrapper).
  • API Testing Client: Postman v10+ or cURL.

5.2 Mandatory Startup Order

CRITICAL: Services must be launched in strict order to allow service registration and route propagation before traffic flows.
  1. Start Eureka Naming Server First (Port 8761):

    Run com.voyagecraft.eurekaserver.EurekaServerApplication. Wait ~5 seconds and verify that the dashboard opens at http://localhost:8761.

  2. Start API Gateway (Port 9090):

    Run com.voyagecraft.apigateway.ApiGatewayApplication. Gateway will connect to Eureka and initialize reactive routes.

  3. Start All Business Microservices (In Any Order):
    • auth-service (Port 8081) - AuthServiceApplication
    • package-service (Port 8082) - PackageServiceApplication
    • payment-service (Port 8083) - PaymentServiceApplication
    • booking-service (Port 8084) - BookingServiceApplication

5.3 Running via Terminal / Command Prompt

# Open separate terminal windows for each service:
cd s:\soaa\eureka-server   && mvn spring-boot:run
cd s:\soaa\api-gateway     && mvn spring-boot:run
cd s:\soaa\auth-service    && mvn spring-boot:run
cd s:\soaa\package-service && mvn spring-boot:run
cd s:\soaa\payment-service && mvn spring-boot:run
cd s:\soaa\booking-service && mvn spring-boot:run

5.4 Running in Eclipse / Spring Tool Suite (STS) / IntelliJ

  1. Import the root folder or individual project folders as Existing Maven Projects.
  2. Right-click each Application class (e.g. EurekaServerApplication.java) → Run As → Spring Boot App.
  3. Use the STS Boot Dashboard to monitor all 6 microservices simultaneously.
